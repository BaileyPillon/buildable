# BUILDLOG: adobe-acrobat-pro

## The prompt (verbatim)

> Build me a private PDF toolkit as an installable PWA with no backend and no accounts. Stack: Vite, TypeScript, pdf-lib for editing, pdf.js for rendering, and tesseract.js for optional OCR, all running in the browser so files never leave my device. Core features: (1) merge several PDFs and drag to reorder pages, (2) split by page range or extract pages, (3) rotate and delete pages, (4) fill form fields and add typed or drawn signatures and text boxes, (5) compress by re-rendering pages as JPEG at a chosen quality, with a warning that this flattens text, (6) OCR a scanned PDF into a searchable one. Keep only a recent-files list of names in IndexedDB, never file contents. Include unit tests for merge, split and rotate using small sample PDFs. Deploy free to Cloudflare Pages or GitHub Pages and explain how to install it from the browser. Finish with a README listing what it cannot do compared with Acrobat Pro.

Host constraints added on top (not part of the prompt): static web app, all libraries bundled locally, relative base `./`, must work under
`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; frame-ancestors 'none'; form-action 'none'; base-uri 'self'; object-src 'none'`
(no inline scripts, no eval, no blob: workers), skip deploying, copy the build to `D:\buildable\public\rebuilt\adobe-acrobat-pro\`.

## What I built

Vite 8 + TypeScript 7 single-page app "Private PDF Toolkit", PWA (manifest, generated service worker, PNG + SVG icons, in-app install button and install help), six tools:

1. **Merge & organize**: add several PDFs, thumbnail grid of every page (lazy pdf.js rendering), HTML5 drag-and-drop reorder plus move buttons, per-page and bulk rotate, delete with undo, output via `assemble()` in pdf-lib.
2. **Split & extract**: thumbnails you can click to select, range text box (`1-3, 5, 8-`), modes: extract to one PDF, one PDF per range, every N pages; multiple outputs download individually or as a hand-written .zip.
3. **Rotate and delete**: inside Merge & organize (prompt item 3), and as tested library functions `rotatePages` and `deletePages`.
4. **Fill & sign**: pdf.js renders pages; pdf-lib reads AcroForm fields and positions real HTML inputs over the widgets (text, multiline, checkbox, radio, dropdown, list); text boxes (3 standard fonts, size, colour, drag); signature dialog with Type (system script fonts) and Draw (pointer canvas) tabs producing a transparent PNG, placeable, movable, resizable; optional flatten; export via pdf-lib. Preview/export alignment checked in the browser.
5. **Compress**: pdf.js renders each page, canvas to JPEG at chosen quality and DPI (presets + sliders), pdf-lib rebuilds. A warning panel plus a required "I understand" checkbox about flattening text; before/after size, warns if the output is larger.
6. **OCR**: tesseract.js in a worker; recognized words become an invisible (render mode 3) text layer on the original pages (kept as images), with rotated-page and crop-box handling; optional skip of pages that already have text; cancel; .txt export; "save OCR files for offline use" button.

Recent files: IndexedDB store with only `{key, name, size, tool, openedAt}`; whitelisted at write time; tested with fake-indexeddb that extra fields are dropped. Clicking an entry goes to the tool with a "pick the file again" banner (browsers cannot reopen by name).

Tests (vitest, 49 passing): merge, split, extract, rotate, delete, reorder with sample PDFs in `tests/samples/` (generated by `scripts/make-samples.mjs`), ranges, ZIP, geometry, forms, annotations, OCR text layer (verified by extracting text back with pdf.js in Node), recent-files store.

Extras: `.github/workflows/deploy-pages.yml`, `public/_headers` (CSP for Cloudflare Pages), CSP also injected as a `<meta>` in the built index.html, `scripts/serve-csp.mjs` to test under the policy, README with deploy and install steps and a long "cannot do vs Acrobat Pro" list.

## Key decisions

* **WebAssembly is blocked by the given CSP** (tested in Chromium: `script-src 'self'` without `'wasm-unsafe-eval'` refuses `WebAssembly.Module`, also in workers). Current tesseract.js (7.x) is wasm-only, so it cannot run under the policy. I pinned **tesseract.js 2.1.5 + tesseract.js-core 2.2.0**, which includes a pure-JS asm.js core, and choose wasm vs asm.js at run time with a feature test. Under the strict CSP, OCR works (about 6 s for a sparse page at 150 DPI; text recognized correctly and extractable via pdf.js). Same feature test sets pdf.js `useWasm: false`.
* No blob: worker: tesseract `workerBlobURL: false` with a same-origin `worker.min.js`; pdf.js worker is a hashed same-origin `.mjs` from `?url`. No eval (`isEvalSupported` not needed in this pdf.js version).
* Vendor assets (pdf.js standard fonts/cmaps/icc/wasm, tesseract worker/cores/English `best_int` model) are copied from node_modules into `public/vendor` by `scripts/copy-assets.mjs` on `predev`/`prebuild`; all URLs are built from `document.baseURI`.
* **Headless renders use pdf.js `intent: 'print'`** (compress, OCR) because the default path waits on `requestAnimationFrame`, which stalls in background tabs.
* Editing coordinates are stored in "view points" (rotation applied, origin top-left) and converted to PDF space by one tested function (`geometry.ts`), shared by text boxes, signatures and the OCR layer.
* Merge/split copy pages (`copyPages`) in one call per source so shared resources are not duplicated; rotation edits in place.
* Service worker is generated at build time (`scripts/sw-plugin.ts`) with a precache list of the app shell; big optional assets (OCR, cmaps, wasm) are cached on first use.
* One panel per tool is mounted once and hidden/shown, so switching tabs does not lose work.

## Not done, or only partly

* **Deploying**: skipped as instructed; I provide the Pages workflow, `_headers`, and README steps instead.
* **Service worker / install could not be exercised**: the in-app test browser refuses every service worker registration (even a trivial one), so offline mode and the install prompt are untested here. The code follows the standard pattern and the manifest/icons are in place.
* OCR is English only; under the strict CSP it uses the slower JavaScript core.
* Pointer-based touch drag-reorder is not implemented (HTML5 drag events); move buttons are the touch alternative.
* Password-protected PDFs are rejected with a clear message (pdf-lib cannot decrypt).
* The bundle still contains tesseract.js 2.x's default CDN URL strings as dead defaults; they are always overridden (`workerPath`, `corePath`, `langPath`) and nothing is fetched from them.
